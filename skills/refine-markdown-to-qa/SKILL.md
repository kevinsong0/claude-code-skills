# Markdown 转 Q&A 格式处理器（基于 XAI glm-4.7）

## 功能概述

通过调用 XAI 的 glm-4.7 模型，将源目录中的所有 `.md` 文件逐个转换为高质量的问答格式，每个输出文件包含一个或多个自包含的问答对。转换过程中保持原文语义，通过 AI 深度增强逻辑性、补充背景和深化解释来提升内容质量。

## AI 模型配置

- **API 端点**: https://api.xairouter.com/v1/chat/completions
- **模型**: glm-4.7 (XAI)
- **Prompt**: "整理为问答的形式，尽量详细"

## 使用方法

### 基本用法

```python
from refine_markdown_to_qa import refine_markdown_to_qa

# 使用默认目标目录
result = refine_markdown_to_qa(
    source_dir="C:/Users/sksua/Nutstore/1/Obsidian (1)/Fcards"
)

# 指定自定义目标目录
result = refine_markdown_to_qa(
    source_dir="C:/Users/sksua/Nutstore/1/Obsidian (1)/Fcards",
    target_dir="C:/Users/sksua/Nutstore/1/Obsidian (1)/Q&A",
    preserve_original=False
)
```

### 命令行调用

```bash
cd refine-markdown-to-qa/scripts
python refine_markdown_to_qa.py "C:/Users/sksua/Nutstore/1/Obsidian (1)/Fcards"
```

### 返回值

```python
{
    'success': ['file1.md', 'file2.md'],
    'failed': {
        'file3.md': '错误信息'
    }
}
```

## 参数说明

### source_dir (必需)
源目录路径，包含待处理的 Markdown 文件。支持相对路径和绝对路径。

### target_dir (可选)
目标目录路径，用于存放处理后的 Q&A 文件。
- Windows 默认: `C:\Users\sksua\Nutstore\1\Obsidian (1)\Q&A`
- 其他系统默认: `~/Nutstore/1/Obsidian (1)/Q&A`

### preserve_original (可选，默认: False)
是否保留原始文件副本。
- `True`: 原文保留在源目录，Q&A 文件另存为新文件
- `False`: 原文移动到 `target_dir/archive`，Q&A 文件保存在源目录

## Q&A 转换规则

### 问题生成（Q）

1. **提炼核心主题**
   - 识别原文的主要观点、概念或论题
   - 提取关键词作为问题核心

2. **构建问题句式**
   - 定义类: "什么是...?"、"...的定义是什么?"
   - 原理类: "如何理解...?"、"...的工作原理是什么?"
   - 原因类: "为何...?"、"...的原因是什么?"
   - 方法类: "如何...?"、"实现...的最佳方式是什么?"

3. **问题独立性**
   - 问题应能独立传达主题
   - 无需依赖外部上下文即可理解
   - 避免模糊或过于宽泛的表述

### 回答生成（A）

1. **整合原文信息**
   - 保留原文核心内容
   - 保持原有的案例、数据、引述
   - 维持原文的逻辑结构

2. **增强内容质量**
   - 补充必要的背景知识
   - 增加逻辑衔接词句
   - 解释抽象概念
   - 扩展重要观点

3. **提升可读性**
   - 使用专业但自然的语言
   - 保持段落连贯性
   - 避免口语化表达
   - 消除冗余信息

4. **结构优化**
   - 确保语义完整
   - 保持结构连贯
   - 避免碎片化
   - 支持多级列表、代码块等格式

## 输出格式规范

### 单主题文件

```markdown
## Q: 什么是认知负荷理论？

A: 认知负荷理论（Cognitive Load Theory, CLT）由 John Sweller 于 1988 年提出，旨在解释人类工作记忆在信息处理中的有限容量如何影响学习效率...

（后续为完整段落，保持原文格式）
```

### 多主题文件

```markdown
## Q: 什么是认知负荷理论？

A: 认知负荷理论...

## Q: 认知负荷有哪些类型？

A: 认知负荷主要分为三种类型：内在认知负荷、外在认知负荷和关联认知负荷...
```

### 格式要点
- 问答对之间保持空行分隔
- 保留原文的 Markdown 格式（列表、代码块、引用等）
- 每个问答对应一个独立主题

## 文件操作说明

### 处理流程

1. **遍历源目录**
   - 识别所有 `.md` 文件
   - 按文件名排序处理（可选）

2. **逐个处理文件**
   - 读取文件内容
   - 识别主题并转换为 Q&A 格式
   - 写入 Q&A 文件
   - 移动或保留原文

3. **错误处理**
   - 单个文件失败不影响其他文件
   - 记录失败文件和错误信息
   - 返回处理结果摘要

### 文件命名策略

- `preserve_original=True`: 原文件名不变，Q&A 文件命名为 `{原文件名}_QA.md`
- `preserve_original=False`: Q&A 文件使用原文件名覆盖，原文移动到归档目录

### 归档目录

当 `preserve_original=False` 时，原文移动到：
```
{target_dir}/archive/
```

## 错误处理策略

### 继续处理原则

- 单个文件处理失败时，继续处理其他文件
- 记录失败信息到返回值
- 不因个别错误中断整体流程

### 常见错误类型

1. **文件读取错误**
   - 文件不存在
   - 权限不足
   - 编码问题

2. **内容转换错误**
   - 空文件
   - 无法识别的主题
   - 格式解析失败

3. **文件写入错误**
   - 目标目录不存在
   - 磁盘空间不足
   - 权限不足

### 错误日志

所有错误信息都会记录到返回值的 `failed` 字段中，包含：
- 文件名
- 错误类型
- 详细信息

## 最佳实践

### 批量处理前

1. 备份原始文件
2. 确认目标目录权限
3. 检查文件编码（建议 UTF-8）

### 处理后

1. 检查返回值中的 `failed` 字段
2. 抽样检查 Q&A 文件质量
3. 验证原文归档情况（如适用）

### 内容优化建议

- 为复杂主题拆分多个问答对
- 为长文本添加分节标题
- 使用列表清晰呈现要点
- 为代码添加注释说明
